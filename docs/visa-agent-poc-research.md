## 0. 结论先说

三条最重要的：

1. **PoC 范围定在访客签证（Standard Visitor）。** 它是唯一没有外部前置文件依赖、客户手上材料就能凑齐一整套申请的类别，两天能端到端跑通；同时它的核心审查标准是主观判断题，能真正体现"顾问"而不是"填表机器"。

2. **英国的移民建议是持牌行业，这是产品定位问题，不是 PoC 的开发障碍。** 依据 1999 年《移民与庇护法》，在英国境内以经营方式向特定个人提供移民建议，必须持牌，否则构成刑事犯罪；免费也算。这直接决定了产品的责任主体怎么设计，细节见第 3 节。结论是：agent 做顾问的手和眼，持牌顾问做嘴和签字。这条路线同时也是交付稳定性的最优解。

3. **架构上应该是"流程为骨架、agent 为器官"，不是纯 agent。** 这个业务的失败代价高度不对称：多问客户一句只是啰嗦，漏一份材料是拒签、£135 不退、客户行程报废、还可能留下拒签记录影响以后申请。不对称的代价必须由确定性结构兜底。理由和逐环节判断见第 6 节。

## 1. 为什么选访客签证

| 类别 | 前置依赖 | 两天可行性 | 顾问价值 | 判断 |
|---|---|---|---|---|
| 访客签证 Standard Visitor | 无 | 高 | 高（主观审查） | **选它** |
| 学生签 Student | 学校签发 CAS | 低 | 中 | 排除 |
| 工签 Skilled Worker | 雇主签发 CoS + 担保牌照 | 低 | 中 | 排除 |
| 配偶/伴侣 Appendix FM | 无，但举证极重 | 低 | 极高 | 排除（见下） |

学生签和工签都卡在一份由第三方机构签发的前置文件上，agent 既拿不到也造不出来，演示会在第一步就断掉。

配偶签的顾问价值其实是最高的，材料最厚、判断最难，但两天做不完；而且它涉及收入门槛和关系真实性举证，做错对客户的伤害远大于一次访客签拒签。不适合当第一个 PoC。

访客签证的好处是：申请人自己手上的材料（护照、流水、在职证明、行程、担保人材料）就构成完整的一套，闭环短；而且它的审查标准恰好是"没有硬指标、全靠综合判断"，这正是人类顾问在做的事。

**演示场景建议：探亲访问 + 英国定居亲属担保。** 这是访客签证里最容易被拒的情形——申请人在英国有定居亲属，内政部会把这当成"留下来的动机"（pull factor），需要顾问主动去补强反向证据。如果只演示"有稳定工作、去伦敦玩一周"的简单客户，看不出 agent 和填表工具的区别。

## 2. 业务底层：内政部到底在审什么

### 2.1 三层结构

访客规则在《移民规则》Appendix V，申请要过三关：

- **Validity（V2，有效性）**：在线申请、缴费、录生物信息、身份证件齐全。形式关，缺了直接作废。
- **Suitability（V3，适格性）**：Part 9 一般拒签理由，比如犯罪记录、此前使用虚假材料。
- **Eligibility（V4 起，符合性）**：核心是"真实访客"测试。

### 2.2 真实访客测试（V 4.2）——整个业务的重心

申请人必须让签证官相信四件事：

- (a) 会在访问结束时离开英国；
- (b) 不会通过频繁或连续入境的方式长期居留，或把英国变成主要居所；
- (c) 确实是为规则允许的目的入境；
- (d) 有足够资金覆盖此行全部合理费用，无需工作也无需动用公共福利。

**关键点：签证官不满意就必须拒签，没有酌情空间。** 而且 (a) 这一条——"会不会按时离境"——是最常见的拒签原因。

### 2.3 签证官实际权衡的因素

来自内政部对内的《Visit caseworker guidance》（2026 年 2 月更新版），这是最有价值的一份材料，因为它写的是审查逻辑而不是申请须知：

- 以往的出入境记录，包括去英国和去其他国家的记录；
- 以往访问的停留时长，以及是否明显超过当初申报的时间；
- 财务状况，以及家庭、社会、经济背景；
- 与常住国之间的个人和经济联系；
- 最近 12 个月内累计在英停留时间和出行模式。

良好的守法出入境记录是正面信号；被其他国家拒签或遣返是负面信号。

**明确列出的疑点信号：**

- 申请人在常住国几乎没有家庭和经济联系，却在英国有多名亲属；
- 申请人和担保人的陈述之间存在矛盾；
- 提供的信息经核查无法验证。

### 2.4 资金要求

**没有法定最低金额。** 判断标准是：收入扣掉现有固定支出后，能否合理覆盖此行开销。这一点对产品很重要——不能写死一个数字去卡客户，必须做成一个可解释的匹配判断。

第三方出资是允许的，但出资人必须与申请人有真实的职业或私人关系，且这笔支持本身不能违反移民法。签证官会查：关系是否真实（联系频率、见面记录）、担保人以往是否担保过其他访客、担保人的钱够不够同时养自己和申请人。

### 2.5 材料清单（实务）

规则本身不给硬性清单，实务上一套完整的探亲访问申请通常包含：

- 护照（覆盖整个停留期）及既往签证页；
- 近 6 个月银行流水；
- 在职证明、准假信、工资单（或营业执照、完税记录，如自雇）；
- 住宿证明；
- 往返机票预订或行程安排；
- 与常住国联系的证据（房产、社保、在读子女、赡养责任等）；
- 担保人材料：担保信、担保人身份或居留证明、担保人流水、住址证明；
- 非英文材料的认证翻译件。

其他事实：可提前 3 个月申请；每位家庭成员各自申请、各自缴费；六个月访客签 £135，十年多次往返 £1,128；递交生物信息后通常 3 周内出结果。

### 2.6 拒签高发情形

自由职业或非正规就业、刚换工作或待业、新近自雇、主要依靠英国亲属出资、常住国联系薄弱、英国有定居直系亲属。这几类恰恰是最需要顾问的客户。

## 3. 一个必须知道的合规约束

### 3.1 法律事实

- 依据 1999 年《移民与庇护法》第 82 条，"移民建议"指针对**特定个人**、就**相关事项**给出的建议；"相关事项"明确包含所有移民申请。
- 未取得资质而提供移民建议或服务是**刑事犯罪**。
- 监管机构原为 OISC，自 2025 年 1 月 16 日起更名为 Immigration Advice Authority（IAA）。
- 监管范围看**提供方所在地**：在英国境内提供才受管，客户在境外不影响。境外机构向境外客户提供则不在 IAA 管辖内。
- "以经营方式"包括非营利机构，也包括免费提供。只有偶尔帮直系亲属和密友、且不收费，才不需要持牌。

### 3.2 界线画在哪

监管机构自己的《Immigration Assistance》操作指引给了一个非常贴近我们产品的例子。一位会计师帮客户准备用于签证申请的财务报表：

- **可以做**：编制账目本身；就"哪类证据适合他的业务情况"提出意见；提示某些问题需要另找专业意见。
- **不可以做**（除非持牌）：协助他填写申请表；判断他的材料或他的情况**是否满足申请要求**。

另外，发布不针对个案的通用信息不受监管；一旦结合具体个人情况给出"你应该怎么做"的意见，就落入监管。指引原文对"建议"的定义是：基于对方提供的信息，就其可采取的行动方案或选项给出意见。

**这条界线正好穿过我们产品的核心价值。** "像人类顾问一样带客户准备材料"，其中的材料质检和风险诊断，本质就是在判断"你的情况够不够"。

### 3.3 三条路线

| 路线 | 做法 | 评价 |
|---|---|---|
| A. 持牌顾问在环 | agent 做收集、质检、起草，持牌顾问复核签字，责任主体是顾问 | **推荐。** 合规清晰，且与交付稳定性的要求天然一致 |
| B. 主体设在英国境外 | 利用属地原则 | 取决于实际经营地和团队所在地，容易踩线；客户也失去监管保护，不利于建立信任 |
| C. 只做非监管动作 | 通用信息、材料收集物流、翻译、提醒 | 合规最稳，但价值主张被掏空，变成一个催收机器人 |

**建议路线 A。** 它带来一个额外好处：合规上必须存在的"顾问复核"关口，恰好就是 AI 交付稳定性上必须存在的"人审"关口。两个约束指向同一个架构，不用做取舍。

**这不阻塞 PoC。** PoC 是内部演示，不对外提供服务。只需要两件事：演示流程里把"顾问复核"这一步显式做出来（它本来就是加分项，说明产品想清楚了）；上生产的 TODO 里带上责任主体的落实。

## 4. 顾问工作流与双渠道分工

### 4.1 把顾问的工作拆开

| 阶段 | 顾问在做什么 | 产出 |
|---|---|---|
| 1 资格初筛 | 确认国籍是否需要签证还是 ETA、访问目的是否属于允许范围、时间是否来得及 | 接不接这个案子 |
| 2 案情画像 | 问出职业、收入、资金、家庭、出行史、担保人情况 | 结构化案情档案 |
| 3 风险诊断 | 对照真实访客测试，找出这个客户的薄弱点 | 风险清单 + 补强方向 |
| 4 清单定制与收集 | 给出针对性清单，反复催收，回答客户疑问 | 材料齐了 |
| 5 材料质检 | 查完整性、一致性、时效性、可读性、翻译 | 退回重做或通过 |
| 6 组稿交付 | 表格答案、说明信、打包 | 交付物 |

第 3 步是顾问真正值钱的地方，也是 agent 最该证明自己的地方。第 4 步占掉顾问最多时间，也是 agent 最容易产生效率收益的地方。

### 4.2 两个渠道各干什么

不是"两个渠道都能聊天"，而是它们的物理特性不同：

**WhatsApp** —— 低摩擦、高频、移动端。适合：初筛问答、案情访谈、催收提醒、拍照上传材料、进度通知、零散答疑。
**邮件** —— 结构化、可存档、能带附件和长文档。适合：正式的材料清单、质检反馈报告、最终交付包、需要客户留存和回看的东西。

分工原则：**对话在 WhatsApp，文档在邮件。** 客户不会在 WhatsApp 里认真读一份 20 项的清单，也不会在邮件里一天回你八次。

### 4.3 WhatsApp 的硬约束（影响流程设计，Ian 需要知道）

- 客户发来消息会开启一个 **24 小时会话窗口**，窗口内可以自由发送文本、图片、文档；客户再次发消息会重置计时。
- **窗口关闭后，只能发送 Meta 预先审核过的模板消息。** 这意味着"催客户交材料"不能想发就发，必须设计成有限次数的模板推送，且模板要提前报审。
- **2026 年 10 月 1 日起计费模型变更**：原本在 24 小时窗口内免费的服务消息和实用类模板消息将按条计费。催收节奏的设计会直接变成钱，需要在生产阶段重新算账。

### 4.4 交付物具体长什么样

这是"交付结果"的定义，建议就按这四件：

1. **个性化材料清单** —— 每一项标注：为什么需要（指回哪条规则或哪个风险点）、什么格式、已收到还是待补。
2. **申请表答案草稿** —— 客户需要填进 gov.uk 在线表格的关键答案，逐项给出。注意：由我们代填代交属于监管行为，PoC 不做提交。
**交付边界（与 @Ian 确认一致）**：英国内政部没有对第三方开放的申请提交接口，正式申请只能由申请人自己走 GOV.UK 在线服务，生物信息另走签证中心预约。所以"自动提交"不是 PoC 砍掉的功能，而是长期都接不上的一步。这与第 3 节的监管界线指向同一个结论：**产品的天花板就是交出一套齐备、已校验的材料包，由客户或持牌顾问自己去官方渠道提交。**

3. **说明信（cover letter）草稿** —— 顾问最经典的交付物，把客户的情况和真实访客测试逐条对应起来，尤其解释弱点。
4. **质检报告** —— 哪些材料有问题、为什么、怎么改。

## 5. AI 交付稳定性

### 5.1 这个领域真正的失败模式

不是"回答得不够好"，是下面这些：

1. **规则过时** —— 费用、政策、表格会变。把规则写进 prompt 等于把易变信息埋进代码。
2. **凭空编出要求，或漏掉必需项** —— 漏一项材料直接导致拒签，代价远高于多问一句。
3. **越界给建议** —— 见第 3 节。
4. **诱导或默许造假** —— **最危险的一条。** 模型出于"帮客户把案子做得更好看"的倾向，可能建议修饰资金流水、编造行程、美化在职证明。后果极重：依据移民规则 9.7.1，提供虚假陈述属于强制拒签、无酌情空间，即使非故意也会导致拒签；被认定为故意欺骗的，会触发 **10 年入境禁令**，且禁令从使用欺骗之日起算。这一条必须在架构层面硬性阻断，只在 prompt 里写一句"不要造假"是不够的。
5. **长对话状态丢失** —— 客户信息散落在几十条 WhatsApp 消息里，靠对话历史记忆必然出错。
6. **跨渠道身份错配** —— WhatsApp 号和邮箱必须绑定到同一个案子。

### 5.2 五道防线

1. **状态外置。** 案情档案（case file）是唯一真相源，用固定 schema 存储。模型每轮从它读、往它写，不依赖对话历史。这一条同时解决失败模式 5 和 6。
2. **规则外置。** 材料清单和判断规则做成带"生效日期 + 来源链接"的数据，不是模型记忆。规则变更只改数据。
3. **输出受限。** 交付物用模板渲染，模型只负责填字段，不自由生成法律文本。清单绝不由模型即兴生成，必须从画像按规则映射出来。
4. **断言可溯源。** 每一句"你需要 X"都要能指回具体规则条目。指不回去的，不许出现在交付物里。
5. **人审关口。** 交付前必须有持牌顾问复核签字。PoC 里做成一个显式的、演示时看得见的步骤。

6. **不下"够不够"的结论。** 这是 @Ian 提出的补充，比我原来的写法更严。真实访客测试没有硬标准，所以"你的离境意图证据够了"这类判断既无法验证、错了代价又是拒签。agent 允许做的是**按项检查有没有、齐不齐**，并把缺口讲清楚；不允许做的是成功率预测、"这样就能过"的结论、以及任何强度评估。强度由人类顾问定调。

   这条界线还有个好处：它跟第 3 节的监管界线是同一条。监管指引里会计师"不可以判断材料是否满足要求"，说的就是这件事。合规和稳定性再一次指向同一个设计。

针对造假风险额外加一条：**agent 只能引用客户提供的事实，不能生成或修改任何事实性材料内容。** 说明信可以解释和组织事实，不能创造事实。这一条建议做成独立的输出检查，而不是只写在 prompt 里。

## 6. Agent 还是 Workflow

### 6.1 逐环节判断

| 环节 | 选择 | 理由 |
|---|---|---|
| 资格初筛 | **Workflow** | 决策树，规则明确，必须可复现 |
| 案情画像 | **Agent** | 客户答非所问、信息零散、需要追问，这是自然语言的主场 |
| 风险诊断 | **Agent + 规则校验** | 模型识别风险点并说明缺口，但不下"够不够"的结论（见 5.2 第 6 条） |
| 清单生成 | **Workflow** | 从画像映射到清单是纯规则。**绝不能让模型自由发挥**——漏项的代价太大 |
| 收集催收 | **Workflow** | 状态机加定时任务，还要受 WhatsApp 模板和窗口约束 |
| 材料质检 | **混合** | 格式、时效、完整性用规则；内容一致性（比如流水和在职证明对不对得上）用模型 |
| 说明信起草 | **Agent + 模板约束 + 人审** | 需要语言能力，但必须锁住结构和事实边界 |
| 提交申请 | **不做** | 合规红线，也是风险集中点 |

### 6.2 结论

**骨架是 workflow（一个状态机），只在"理解客户"和"起草文本"两处放 agent。**

理由是代价不对称。这个业务里，多问客户一句话的代价是轻微的啰嗦；漏一份材料的代价是拒签、£135 不退、客户行程报废、还可能在出入境记录上留下拒签痕迹影响后续申请。当失败代价这样不对称时，主导权应该交给确定性结构，模型只在它确有优势的地方介入。

反过来说，纯 workflow 也不行——客户在 WhatsApp 上不会按表单顺序说话，"我表姐在曼城，我想去看看她，大概待仨月吧"这样一句话里同时藏着目的、担保人、时长和一个风险点，这个必须靠模型来拆。

**给 Ian 的落地形态**：一个显式状态机驱动整体推进，每个状态下调用受限的 agent 完成局部任务，agent 的输入输出都过 schema 校验，状态转移由代码判断而不是由模型决定。

---

## 7. 两天怎么切

**第一天**：案情档案 schema、规则与清单数据（先只覆盖探亲访问这一条分支）、WhatsApp 接入（PoC 阶段用 sandbox 或模拟，不等正式账号审核）、初筛与画像 agent。

**第二天**：风险诊断、清单生成、催收状态机、邮件交付物渲染、人审步骤、演示脚本走查。

**明确砍掉**：正式 WhatsApp Business API 账号申请与模板报审、多签证类别、多语言、真实提交、支付、账号体系。

**演示脚本**：故意选一个带弱点的客户——申请人是自由职业者，资金刚好够，姐姐在英国已定居，想去住三个月。看 agent 能不能自己识别出"英国有定居亲属 + 常住国联系薄弱 + 收入不稳定 + 停留时间偏长"这一组风险，主动要求补强，而不是照单收材料。这个案子如果 agent 能处理好，产品价值就说清楚了。

---

## 8. 上生产还欠什么

1. **责任主体**：IAA 注册，或与持牌顾问机构合作并明确权责划分（第 3 节）。
2. **WhatsApp 正式化**：Business API 账号、模板报审、2026-10-01 计费变更的成本重算。
3. **数据合规**：护照、银行流水属于高敏感个人数据，需要按 UK GDPR 处理——加密存储、留存期限、数据处理协议、跨境传输机制。这一项在真实客户进来之前必须做完。
4. **规则更新机制**：监控 gov.uk 变更，规则数据带版本和生效日期。
5. **审计日志**：每一条给客户的建议都要能追溯到当时的规则版本和人审记录。出了纠纷这是唯一的自证材料。
6. **拒签复盘闭环**：拒签信里的理由回流到规则和风险模型，这是这个产品长期变强的唯一途径。
7. **反欺诈**：客户提交伪造材料时的识别和拒接机制，保护自身责任。
