# 英国访客签证 PoC：材料判定规则清单

更新时间：2026-08-22  
适用范围：Standard Visitor，探亲访问 + 英国定居亲属场景  
规则版本：`visitor_family_visit` / `1.0.0`

这份文件把 `config/visitor_family_visit.yaml` 与 `src/validate.py` 中当前实际执行的
判定规则翻译成人可读清单。模型只抽字段；下面的判断由代码完成。

## 一、判定结果怎么解释

- **阻塞失败**：材料不能进入最终包，状态机要求客户重新提交。
- **建议项**：材料仍可接收，但质检报告会保留提示；不会把行业惯例说成法律要求。
- **通过**：配置要求的字段存在，且没有触发阻塞规则。
- **材料包完整**：所有按案情生成的必需材料都已提交，且没有阻塞失败。
- **不代表签证会通过**：系统不评成功率，不判断离境意图或资金“够不够”。强度判断留给人工复核和签证官。
- **未知规则失败关闭**：配置出现代码未实现的 validator 时直接报错，不会静默当成通过。
- **跨材料重检**：每次收到新材料后，系统重新执行全部已收材料的相关规则，避免上传顺序造成漏检。

## 二、逐项判定规则

### 1. 护照个人信息页及既往签证页

阻塞规则：

- 必须读到姓名、护照号、到期日。
- 护照姓名必须与 intake 的申请人姓名一致；允许姓名顺序变化和中间名差异。
- 护照到期日必须晚于计划离英日期。

补充：`prior_compliant_travel=true` 才能把“既往合规出行记录”计入常住国约束覆盖；
普通护照上传本身不会自动算作已证明出行合规。

### 2. 个人银行流水

阻塞规则：

- 必须读到账户名、流水起始日、流水结束日和期末余额。
- 账户名必须与申请人姓名一致。

建议项，不阻塞：

- 流水覆盖不足 180 天时提示“实务上通常期望近 6 个月”，但明确这不是法定要求。
- 流水结束日距质检日超过 31 天时提示更新近期流水。

资金展示规则：只并列显示预计行程成本和已证明余额，不设最低余额，不输出
“足够/不足”的结论。

### 3. 往返行程单或预订记录

阻塞规则：

- 必须读到出发日和返程日。
- 如读到乘客姓名，姓名必须与申请人一致。
- 出发日必须早于返程日。

建议项，不阻塞：

- 行程单返程日与 intake 的计划离英日期相差超过 3 天时提示核对。

### 4. 住宿证明

阻塞规则：

- 必须读到住宿地址。

当前 PoC 会提取房东/接待人姓名及住宿起止日期，但尚未对这些字段执行额外阻塞规则。

### 5. 亲属邀请信

阻塞规则：

- 必须读到担保人姓名、地址和双方关系。
- 邀请信中的担保人姓名必须与“担保人的英国身份或居留证明”一致。

后一条为跨材料规则；即使身份材料后上传，也会回头重检邀请信。

### 6. 担保人的英国身份或居留证明

阻塞规则：

- 必须读到担保人姓名和身份类型。

### 7. 第三方出资人的银行流水

仅在 `third_party_funding=true` 时需要。

阻塞规则：

- 必须读到账户名、流水起始日、流水结束日和期末余额。

当前 PoC 不替人工判断出资关系是否真实，也不判断担保人的资金是否“足够”。

### 8. 雇主证明及准假信息

仅在 `employment_status=employed` 时需要。

阻塞规则：

- 必须读到雇主名称和职位。

建议项，不阻塞：

- 如文件包含准假结束日，该日期与计划离英日期相差超过 7 天时提示核对。

### 9. 工商注册、税务记录和企业流水

仅在 `employment_status=self_employed` 时需要。

阻塞规则：必须同时读到：

- 企业名称
- 注册号
- 税务年度
- 申报收入
- 企业流水起始日
- 企业流水结束日

缺任意一项都会要求补件；仅有企业名称不能通过。

### 10. 常住国约束证据

阻塞规则：

- 必须读到 `tie_types` 描述。

覆盖计算不是“上传过就全算”：

- 就业/经营约束：合格雇主证明，或字段齐全的自雇材料。
- 家庭约束：`tie_types` 含 dependant/dependent、child、parent、mother、father、spouse、family 等词。
- 房产/资产约束：`tie_types` 含 property、apartment、mortgage、house、flat、asset、land 等词。
- 既往合规出行：护照材料明确抽到 `prior_compliant_travel=true`。

## 三、材料清单的条件规则

| 条件 | 生效的材料 |
|---|---|
| 所有申请人 | 护照、个人流水、行程单、住宿证明、常住国约束证据 |
| `has_uk_settled_relative=true` | 亲属邀请信、担保人身份或居留证明 |
| `third_party_funding=true` | 第三方出资人的银行流水 |
| `employment_status=employed` | 雇主证明及准假信息 |
| `employment_status=self_employed` | 工商注册、税务记录和企业流水 |

## 四、来源和规则等级

- `appendix_v`：Immigration Rules Appendix V: Visitor。
- `caseworker_guidance`：Visit caseworker guidance。
- `supporting_docs`：GOV.UK visitor visa supporting documents guide。
- `industry_practice`：行业实务，不是法律要求；原则上以建议项呈现。
- 每项材料和风险规则都必须引用 `config/sources.yaml` 中可解析的 source id；
  无来源规则会出现在质检报告的 `unsourced_rules` 中。

## 五、人工复核关口

材料包生成后状态进入 `human_review`。人工复核者需要确认：

1. 风险观察是否被说明信或补充材料合理回应；
2. 材料之间是否存在代码尚未覆盖的语义矛盾；
3. 模板生成内容是否只引用客户已提供事实；
4. 最终交付没有被误读为成功率预测或申请提交。
